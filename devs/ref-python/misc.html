class app.taxonomy.TaxonomyNode(*, id: str, names: Dict[str, str], parents: List[TaxonomyNode] = [], children: List[TaxonomyNode] = [], synonyms: Dict[str, List[str]] = {}, properties: Dict[str, Any] = {})[source]¶

A taxonomy element.

Each node has 0+ parents and 0+ children. Each node has the following attributes:

  • id: the node identifier, it starts with a language prefix (ex: en:)

  • names: a dict mapping language 2-letter code to the node name for this language

  • parents: the list of the node parents

  • children: the list of the node children

  • properties: additional properties of the node (taxonomy-dependent)

  • synonyms: a dict mapping language 2-letter code to a list of synonyms for this language

Index updates¶

Update daemon: keep an Elasticsearch index up to date from Redis streams.

Applications publish the documents that changed to a Redis stream. This module consumes such a stream, fetches each changed document and writes it to the index, forever.

Two properties matter here:

  • no lost event: the position reached in the stream is persisted in Redis after each handled event (see app.checkpoints), so a restart resumes where it stopped, and an event is never acknowledged before being indexed;

  • no crash on a transient error: Elasticsearch and Redis outages are retried with an exponential backoff, instead of stopping the daemon.

The reader of the stream (app._import.get_new_updates()) and the document fetchers are shared with the import process, which uses the same stream to catch up with the events published during a full import.

class app.updates.UpdatesStateRecorder(redis_client: Redis, stream_name: str, index_name: str, interval: float = 10.0, clock: Callable[[], float]=<built-in function monotonic>)[source]¶

Record the processing state of the daemon for the health endpoint.

The state (the ID of the last event read by the daemon and the number of read events still to be processed) is informational: writing it must never slow down or break the daemon. Writes are therefore throttled to at most one per UPDATES_STATE_WRITE_INTERVAL seconds, and errors are logged and ignored.

A throttled write is “leading edge”: the value is written as soon as it changes after the interval, the intermediate values being skipped. The stream being quiet is the signal to flush the latest value (see flush_if_due()), so that the state settles at its final value when the daemon has nothing left to do.

app.updates.index_result_and_track_event(redis_client: Redis, es_client: Elasticsearch, stream_name: str, stream_id: str, result: FetcherResult | None, processor: DocumentProcessor, index_name: str, stop_event: Event) → str | None[source]¶

Index an event and persist the position it allows to resume from.

Both steps are retried on transient errors (see retry_until_done()). The position is only persisted once the event has been handled (indexed, removed, skipped or permanently failed), which gives at-least-once semantics: after a crash, the last unconfirmed event is processed again (indexing is idempotent).

Parameters:

  • redis_client – the Redis client, storing the checkpoints

  • es_client – the Elasticsearch client

  • stream_name – the name of the Redis stream

  • stream_id – the ID of the event in the stream

  • result – the document fetched from the stream, or None if the document is not to be indexed (e.g. because it was already handled)

  • processor – the document processor of the target index

  • index_name – the index (alias) the documents are written to

  • stop_event – if set while retrying, give up

Returns:

the stream cursor to use to read the next event, or None if the daemon was stopped before the event could be handled

app.updates.reset_checkpoint_after_import(es_client: Elasticsearch, config: IndexConfig) → None[source]¶

Move the update daemon checkpoint to the end of the imported data.

The import already took into account the stream events up to the most recent document (see app._import.get_redis_updates()), and the alias now points to the new index. Keeping the previous checkpoint would only cause a (harmless but wasteful) replay of old events by the daemon.

This is best effort: a failure here is logged and does not fail the import, since a stale checkpoint only leads to a replay.

Parameters:

  • es_client – the Elasticsearch client

  • config – the index configuration used for the import

app.updates.retry_delay(attempt: int) → float[source]¶

Return the delay to wait before the n-th retry of a transient error.

The delay is RETRY_INITIAL_DELAY doubled on each attempt, capped at RETRY_MAX_DELAY, with a random jitter of +-RETRY_JITTER (relative) so that several processes don’t retry at the exact same time.

Parameters:

attempt – the number of retries already performed (0 for the first)

Returns:

the delay in seconds

app.updates.retry_until_done(what: str, func: Callable[[], None], stop_event: Event, skip_non_retryable: bool = True) → bool[source]¶

Call func, retrying on transient errors until it is done.

Transient errors (see is_retryable_error()) are retried with an exponential backoff, forever: no event is ever skipped because of a temporary Elasticsearch or Redis outage. Non-retryable errors are logged and skipped by default, so that a single invalid document cannot block the whole stream forever (the checkpoint is still advanced by the caller, which means the document is only re-indexed if it changes again).

Parameters:

  • what – a short description of the operation, for logging

  • func – the (idempotent) function to call

  • stop_event – if set while waiting, give up retrying and return

  • skip_non_retryable – if True (the default), a non-retryable error is logged and the operation is skipped. If False, it is re-raised to the caller (used for operations that must not be silently dropped).

Returns:

True if the operation was not canceled, False otherwise

app.updates.run_update_daemon(config: Config) → None[source]¶

Run the update import daemon.

This daemon listens to the Redis stream containing information about updated documents, fetches the full document and indexes it in Elasticsearch.

Its position in the stream is persisted in Redis (see app.checkpoints) after each handled event, so that a restart resumes where it stopped instead of skipping the events published meanwhile. Transient Elasticsearch/Redis errors are retried with a backoff instead of crashing the process. If the index is empty and there is no checkpoint yet, it waits for the import to populate the index before starting.

Parameters:

config – the configuration to use

app.updates.wait_for_start_position(redis_client: Redis, es_client: Elasticsearch, stream_name: str, index_name: str, last_modified_field_name: str, stop_event: Event) → str | None[source]¶

Wait for the index to be populated, then return the stream ID to start reading from.

The position is read from the persisted checkpoint. If there is none (first run, or checkpoint deleted), it is derived from the most recent document of the index, so that events published while the daemon was not running are not lost.

Deriving that position requires the index to be populated (usually by an import). As long as it is empty, the daemon waits: starting from the end of the stream instead would silently drop the events published meanwhile. A stop request interrupts the wait.

Parameters:

  • redis_client – the Redis client

  • es_client – the Elasticsearch client

  • stream_name – the name of the Redis stream

  • index_name – the name of the index alias the events are written to

  • last_modified_field_name – the field holding the last modification timestamp of the documents

  • stop_event – if set while waiting for the index, give up

Returns:

the stream ID to start from, or None if the daemon was asked to stop while the index was still empty

Persist the position reached in a Redis stream.

The update daemon reads a Redis stream to know which documents changed. To be able to resume where it stopped after a restart (deployment, crash, ES blip), it stores the ID of the last handled stream entry in Redis.

A checkpoint is identified by both the stream name and the index alias the events are written to, because the same stream may be consumed for different indexes.

This module also stores informational processing state of the update daemon (set_updates_state()), read by the health endpoint. It lives under its own key prefix, so that it can never interfere with the durability contract of the checkpoints.
